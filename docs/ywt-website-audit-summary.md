# 王者演武堂网站审计总结

- 审计对象：<https://ywt.yunhe.ink/>
- 审计日期：2026-07-20（美国东部时间）
- 审计方式：公开页面浏览、移动端与桌面端检查、网络响应与页面结构分析、PageSpeed/Lighthouse 测试
- 审计边界：仅进行非破坏性、未登录状态评估；未审查源代码、数据库、服务端权限逻辑，也未实施主动渗透测试

## 一、总体结论

网站已经具备较完整的王者荣耀资料站雏形：英雄与装备数据量较大，搜索、筛选、英雄详情等核心功能可用，视觉风格也较统一。作为个人项目，完成度较高；若按正式上线产品衡量，目前仍存在明显的性能、无障碍、SEO、账户安全和信息可信度问题。

**综合评价：**

- 个人项目完成度：**7.3 / 10**
- 生产级产品成熟度：**5.9 / 10**
- 当前建议：**可以展示和内测，但不建议在修复 P0 问题前承载正式用户账户或公开赛事业务**

## 五、主要问题

### P0：应优先修复

#### 1. 页面布局偏移严重

- 移动端 CLS 为 0.854，桌面端为 0.527，远高于建议值 0.1。
- 可能来源包括：主内容异步加载后突然插入、进入动画改变布局、图片或卡片未预留稳定尺寸，以及大面积动态模糊光球。
- 页面未充分尊重 `prefers-reduced-motion`，对容易晕动的用户不友好。

**建议：**为异步内容预留固定骨架；所有图片和卡片声明稳定尺寸；动画仅使用 `transform` 与 `opacity`；为减少动态偏好提供静态模式。

#### 2. URL 与移动端路由重复

- 访问首页时存在 `/` → `/m/` → `/m` 的重定向链。
- 桌面端与移动端使用分离 URL，容易产生重复内容、缓存和统计拆分问题。
- 页面未发现完整的 canonical 规范化配置。

**建议：**优先改为同一 URL 下的响应式布局；如果必须保留移动 URL，应配置 canonical、alternate，并消除多余重定向。

#### 3. 搜索引擎基础设施异常

- `/robots.txt` 和 `/sitemap.xml` 会 307 跳转到登录页。
- 不存在的路径也可能被导向登录，而不是返回真正的 404。
- favicon 请求返回 404。

**影响：**搜索引擎可能无法正确抓取站点、识别页面或清理无效 URL。

**建议：**让 robots 和 sitemap 直接返回 200；未知公开路径返回真实 404；补齐 favicon、manifest 与站点图标。

#### 4. 登录与赛事状态表达不一致

- 首页展示公开房间，但赛事大厅可能显示无房间。
- 进入房间详情时先显示骨架，随后才跳转登录，容易让用户误以为页面故障。

**建议：**统一房间数据源和可见性规则；需要登录的页面应立即提示或重定向；明确区分“暂无房间”“无权限”和“加载失败”。

#### 5. 无障碍与键盘操作存在阻断

- 移动底部导航部分控件没有可访问名称。
- “图鉴”等图标按钮缺少明确的 `aria-label`。
- 隐藏菜单虽透明不可见，但链接仍可能进入 Tab 顺序。
- 顶部登录入口显示为尺寸很小的 `?`，触控目标和可理解性不足。
- 存在按钮嵌套在链接内的无效交互结构。
- 忘记密码弹窗缺少 `role="dialog"`、`aria-modal`、焦点陷阱和可靠的 Esc 关闭行为；Tab 可跳回背景页面。

**建议：**补齐控件名称和语义；隐藏内容同步设置 `inert` 或移出 Tab 顺序；重构交互元素；按 WAI-ARIA 对话框模式处理弹窗焦点。

#### 6. 账户恢复与密码规则风险

- 忘记密码流程依赖固定安全问题。此类答案常可被猜测、搜索或通过社工获得，不适合作为安全账户恢复机制。
- 密码最短 11 位；NIST 对仅使用密码的认证通常建议至少 15 位。
- 登录/注册输入项缺少稳定的 `id`、`name`、关联标签与适当的 `autocomplete`。
- 未看到明确的隐私政策和服务条款入口。

**建议：**使用经验证的邮件/短信一次性链接或令牌恢复；提高密码规则并支持密码管理器；完善表单语义；补齐隐私、条款与数据处理说明。

#### 7. 安全响应头不完整

公开页面响应中未发现或未完整配置以下常用安全头：

- `Strict-Transport-Security`
- `Content-Security-Policy`
- `X-Content-Type-Options`
- `Referrer-Policy`
- `Permissions-Policy`
- `X-Frame-Options` 或 CSP `frame-ancestors`

同时，响应暴露了 nginx 与 Next.js 技术特征。

**建议：**在测试兼容性后逐步启用安全响应头；隐藏不必要的版本信息；对认证接口额外核查 Cookie、CSRF、限流、会话失效和权限校验。

### P1：重要优化

#### 8. 装备页图片和 DOM 规模过大

- 121 张装备图直接请求外部图片域名。
- 未观察到系统性的 lazy loading、明确宽高、`srcset` 或 `sizes`。
- 页面高度约 13,301px，DOM 节点约 1,698 个；观察窗口内仍有大量图片未完成加载。

**建议：**使用分页、虚拟列表或折叠分类；首屏外图片延迟加载；指定尺寸和响应式图片；增加图片代理、缓存与失败占位图。

#### 9. 英雄页内容量同样偏大

- 英雄图片已使用 lazy loading，这是优点。
- 但页面仍约有 1,727 个 DOM 节点，高度约 7,627px。

**建议：**考虑分页、分批渲染或虚拟列表，避免一次性挂载全部卡片。

#### 10. 元数据过于单一

- 多个路由使用同一个标题“王者演武堂”和同一条通用描述。
- 未完整发现 canonical、Open Graph、Twitter Card、favicon、manifest 和 `theme-color`。

**建议：**为英雄、装备、赛事、公告等页面生成独立标题与描述，并补齐社交分享和规范化元数据。

#### 11. 内容质量与数据一致性问题

- 部分日期直接显示 Markdown 符号，如 `*2026-07-01*`、`**2026-06-25**`。
- V1.0.0 与“全新开始”等标题存在重复或日期不一致。
- “官方公告”缺少可点击来源链接，可信度不足。
- 搜索筛选后总数仍可能显示 131，反馈不准确。
- 个别英雄职业与说明疑似错配，例如 `元流之子（刺客）` 被标注为辅助/游走并复用辅助文案。

**建议：**建立内容校验规则；在发布流程中检查日期、版本、职业映射、重复标题和来源链接。

### P2：体验提升

- 减少大面积渐变、光晕和持续动画，提升内容可读性。
- 桌面端提供更明确的主导航，避免重要入口依赖隐藏菜单。
- 公告、攻略和数据注明来源、更新时间与适用版本。
- 增加错误监控、性能监控、核心转化事件与搜索无结果统计。

## 六、建议整改顺序

1. 修复 CLS、骨架尺寸和动画策略。
2. 修复 robots、sitemap、404、favicon 及 `/m` 重定向链。
3. 修复弹窗焦点、导航命名、隐藏菜单 Tab 顺序和表单标签。
4. 替换安全问题找回机制，补齐安全响应头与隐私条款。
5. 统一房间数据状态和登录跳转逻辑。
6. 优化装备/英雄长列表、图片加载与 DOM 数量。
7. 完善页面级 SEO 元数据和 canonical。
8. 清理公告、日期、版本、职业映射等内容错误。
