# 王者演武堂 V2.2 动态资源调度架构升级 Codex 开发任务书

## 一、开发目标

本次升级目标是在现有王者演武堂架构基础上，引入页面感知、资源调度和生命周期管理机制。

目标：

-   根据用户当前页面动态加载需要的资源。
-   未使用页面不提前加载。
-   多用户共享公共资源。
-   第一个用户承担冷启动成本，后续用户复用热资源。
-   无用户使用时释放实时资源。
-   后台同步任务不受页面生命周期影响。

## 二、架构调整

保留现有代码职责分层：

    app
    web
    features
    core
    lib

新增系统级架构：

    王者演武堂

    ├── Web 子架构
    ├── 数据子架构
    ├── 同步子架构
    └── 平台管控平面

## 三、Web 子架构

### 路由适配层

负责：

-   页面路由
-   API路由
-   参数解析
-   请求响应转换

禁止：

-   直接操作数据库
-   编写复杂业务逻辑

### 页面渲染层

负责：

-   React组件
-   页面布局
-   UI展示

### 页面交互层

负责：

-   用户操作
-   表单
-   弹窗
-   状态变化

### 页面协调层

负责：

-   判断页面需要哪些资源
-   协调多个模块加载

### Web管控层

负责：

-   登录状态
-   页面权限
-   功能入口控制

## 四、数据子架构

划分：

    MySQL数据
    Redis数据
    本地持久化数据
    临时运行数据
    数据治理层

MySQL：

保存业务事实。

Redis：

保存缓存、锁、临时状态。

本地：

保存图片、视频、截图等文件。

临时：

保存短生命周期数据。

## 五、同步子架构

包括：

    官方资讯同步
    英雄数据同步
    装备数据同步
    同步调度中心

英雄同步：

-   基础信息
-   基础属性
-   技能
-   分路
-   图片资源

装备同步：

-   基础属性
-   被动效果
-   合成路径
-   图片资源

## 六、动态资源调度系统

新增：

Resource Scheduler

负责：

-   页面资源管理
-   数据加载
-   缓存生命周期
-   多用户共享
-   自动释放

## 七、页面资源清单

每个页面必须定义资源。

例如首页：

立即加载：

-   当前用户
-   公告
-   公开赛事

延迟加载：

-   官方资讯
-   平台统计

交互加载：

-   管理功能
-   高级模块

## 八、资源生命周期

状态：

    COLD
    WARMING
    HOT
    IDLE
    EVICTED

COLD：

未加载。

WARMING：

正在加载，多个用户共享同一次加载。

HOT：

正在使用。

IDLE：

无人使用但暂时保留。

EVICTED：

释放。

## 九、多用户共享

禁止：

用户A加载一次，用户B再次加载。

必须：

用户A触发加载任务。

用户B加入已有任务。

最终一次加载，多人共享。

使用：

SingleFlight 请求合并。

## 十、租约机制

页面访问创建Lease。

例如：

进入页面：

创建90秒租约。

持续访问：

定期续租。

离开：

释放租约。

异常退出：

等待租约过期。

## 十一、资源释放规则

释放：

-   页面实时任务
-   SSE连接
-   轮询任务
-   临时计算结果

不释放：

-   MySQL连接
-   Redis客户端
-   后台同步任务
-   已保存业务数据

## 十二、同步原则

同步不能依赖用户访问。

正确流程：

用户访问页面。

↓

检查数据版本。

↓

数据有效直接使用。

↓

数据过期后台刷新。

## 十三、开发阶段

Phase 1：

建立资源模型。

Phase 2：

实现Page Scheduler和Data Scheduler。

Phase 3：

接入首页。

Phase 4：

接入赛事页面。

Phase 5：

接入英雄和装备同步。

Phase 6：

增加资源监控。

## 十四、禁止事项

禁止：

1.  页面直接访问数据库。
2.  用户数据和公共数据混合缓存。
3.  Redis作为唯一数据来源。
4.  用户离开导致后台任务停止。
5.  多用户重复加载公共资源。
6.  一次性大规模重构业务代码。

## 十五、验收标准

必须满足：

-   首页支持冷启动。
-   后续用户复用热资源。
-   多用户不会重复加载公共数据。
-   无用户时实时资源自动释放。
-   英雄同步独立运行。
-   装备同步独立运行。
-   用户数据隔离。
-   资源生命周期可监控。
