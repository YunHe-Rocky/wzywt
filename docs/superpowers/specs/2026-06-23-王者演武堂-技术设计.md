## 一、技术选型

| 层 | 技术 |
|---|------|
| 框架 | Next.js (App Router) |
| 前端 | React + Tailwind CSS |
| 后端 | Next.js API Routes |
| 数据库 | MySQL |
| ORM | Prisma |
| 定时任务 | node-cron |

**选型理由**：前后端一体降低复杂度；MySQL 已有基础设施；Prisma 提供类型安全的数据库操作；node-cron 零外部依赖，满足每日定时同步需求。

## 四、分队算法

### 输入

N 名非观众选手（预期 N=10），每人提供：
- 5 个分路的偏好排名（1-5）
- 各分路下的英雄战力列表

### Step 1 — 分路分配

枚举所有合法分路方案：N 人分配到 5 个分路，每路恰好 N/5 人。

对 N=10（每路 2 人），组合数 ≈ 113,400，全量枚举 < 100ms。

### Step 2 — 分队平衡

每种分路方案下，每路 N/5 人平分到两队，枚举分队组合。

对每路 2 人：2^5 = 32 种。总搜索空间 ≈ 113,400 × 32 ≈ 360 万。

### 评分

```
score = -|sum(红队巅峰战力) - sum(蓝队巅峰战力)| × W1
        + sum(每人分路偏好得分) × W2
```

- 巅峰战力 = 选手所有英雄最高战力值
- W1 ≫ W2，优先保证实力均衡
- 取最高分方案

### 人数不足时

若 N < 10，按实际人数尽量均分两队（标注人数不对称），或多出的人自动归为观众。

## 五、英雄数据同步

- 英雄列表源：`https://pvp.qq.com/web201605/js/herolist.json`
- 技能详情源：`https://pvp.qq.com/web201605/herodetail/{id}.shtml`
- 定时任务：node-cron，每日 06:00 执行
- 同步策略：请求官方数据 → 逐英雄对比本地库（hero_id + updated_at 或字段 hash）→ 新英雄插入 / 有变化的更新 / 无变化跳过
- 初次启动全量拉取，之后增量同步

## 六、权限中间件

API 层统一鉴权（session/cookie），根据 TournamentAdmin 表判定操作权限。

**房主操作冷却**：房主关键操作（分队、踢人、延长截止）写入 AdminOperation 表并记录时间戳。次房主执行同类操作前检查：若 5 分钟内已有房主操作，拒绝并提示。
