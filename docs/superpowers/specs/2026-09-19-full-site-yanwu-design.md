# 王者演武堂全站视觉统一设计定稿

日期：2026-09-19

状态：视觉方向与 v4 效果稿已获认可；本书面范围等待用户复核。本文不是实现完成报告。

## 1. 一句话约定

全站每一个页面都使用用户认可的「新中式现代演武馆」：纸白、墨绿、朱砂、水墨、书卷式标题。电脑和手机同一套设计语言，分别组织布局；不是只换首页颜色，也不是把电脑页面缩小到手机。

统一范围包括：26 类正式页面、各自的电脑与手机入口、9 类后台页面、开屏、通用弹窗和全部可达状态。文化内容须自然融入；功能、权限、真实数据与现有操作入口不能因视觉改版丢失。

## 2. 已认可的视觉基准

- 本地效果稿：`.superpowers/brainstorm/2040-1789799009/content/yanwu-design-v4.html`。
- 截图索引：`test-results/full-site-design-v4/index.html`，含首页、房间大厅、文化阅读、庄重纪念、后台五种状态的桌面/手机样章及开屏过程帧。
- 这批文件只用于视觉参考，不把其中的示例房间、评审工具、演示提示、临时 HTML 样式或伪操作直接带入产品。
- 用户已认可两端统一风格和手机的单一墨色书签导航，并再次强调“每一个都一套”。
- 当前只有关键页面效果稿通过浏览器检查；全站业务 UI 的实现与逐页验收尚未开始。

## 3. 统一设计系统

### 3.1 色彩、排版与材质

| 语义 | 基准 | 使用规则 |
| --- | --- | --- |
| 页面纸底 | `#f5f2ea` | 所有正式页面的基础底色，不保留深蓝背景岛 |
| 面板纸色 | `#fffdf8` | 表单、弹窗、需要独立层级的工作面板 |
| 主文字 | `#252b28` | 正文、数值、表头 |
| 次文字 | `#697064` | 辅助信息，实际组合须检验对比度 |
| 墨绿 | `#426855` | 次强调、文化入口、状态以外的品牌辅助色 |
| 深墨导航 | `#29382f` | 手机书签栏与需要高对比的导航区域 |
| 朱砂 | `#a43e32` | 主操作、当前页签、品牌印章 |
| 分隔线 | `#dcdccf` | 开放式列表、表格、章节边界 |

- 品牌色与成功、警告、危险、蓝/红阵营色分离；危险操作不能只靠“也是红色”来区分，必须有文字、位置和确认步骤。
- 使用一个主题身份 `yanwu` 和一套语义 token，不新增主题切换器、URL hash 换肤或每页独立配色。
- 标题使用可用的中文宋体/衬线字体栈，正文与表单使用系统无衬线字体。不得依赖外网字体，也不引入整套大体积中文字体包。
- 正文以 16px 为基线；辅助说明/导航文字不低于 12px；输入字号至少 16px。v4 中较小的装饰英文不能充当必要操作说明。
- 间距采用 4/8px 节奏，手机水平留白约 20px，320px 窄屏可缩至 16px。桌面沿用窄/中/宽页面壳，不让长正文横贯屏幕。
- 圆角以 4/8/12px 的克制层级为主；头像保持圆形。列表以留白和细线分组，不把每段文字都包进大圆角玻璃卡。
- 首页与文化样章可使用水墨；比赛归档、战术、后台等操作密集区以清晰纸面为主，不铺大幅装饰图。

### 3.2 图像和图标

- 复用 v4 原创水墨意境图；生成记录在 `.planning/2026-09-19-full-site-redesign/asset-notes.md`。它不是史料，也不描绘真实战役。
- 正式落地时生成合适尺寸的本地 WebP/AVIF，声明宽高/比例，首屏以外延迟加载；不直接把 1536×1024 PNG 当每页全屏背景。
- 英雄、装备、头像、战术底图保持业务素材身份和回退行为，不做水墨滤镜以致无法识别。
- 图标沿用 `ArenaIcon` 的代码原生 SVG 体系，补充印章/书签等必要图形；同一层级线宽一致，不用 emoji 代替导航。
- 水墨、印章、墨线都是装饰，不遮挡点击；SVG 字色和描边局部定义，避免原型中全局 stroke 覆盖印章字色的问题。

## 4. 两端布局与导航

### 4.1 共用壳与路由

- 保留 `ThemeLayout` 的标准/全屏分流及 `/m` 路由映射，保留查询参数、登录回跳和浏览器返回行为。
- 标准页面电脑端使用顶部主导航；宽度不超过 900px 时只显示手机底部主导航。两套主导航不能同时可见或同时进入 Tab 顺序。
- 手机顶部只有品牌、个人/登录入口；详情返回属于上下文操作，不再复制全站导航。
- `main-content` 独占全局 gutter 与底栏预留空间；`/m` 不再叠加一层留白。底栏考虑 `safe-area-inset-bottom`，页面末尾按钮滚动后必须完整可见且可点击。
- 登录、注册、后台、debug 沿用专用壳。后台不同时显示前台顶部导航和底部 Dock。

### 4.2 导航完整性与可用边界

- 手机使用 v4 的四项墨色书签外观、纸色当前项和朱砂签。当前阶段四项为：首页、演武、图鉴、动态；个人中心只保留顶部入口，避免重复。
- 图鉴继续提供英雄与装备两个真实目的地，必须有 `aria-expanded`、`aria-controls`、关闭与键盘操作；不能只剩英雄而丢掉装备。
- 电脑主导航覆盖首页、赛事、图鉴、动态；图鉴包含英雄和装备。我的、管理员入口和账户操作归个人菜单；更新日志与现有监控入口仍可达。
- 每个入口保持现有认证与权限规则。游客能看见某功能入口，不代表可以绕过其登录或服务端授权。
- 保留受保护/动态页面的选择性预取策略、待跳转反馈及超时清理，不将所有入口改成无差别预取。
- v4 的“知古”代表文化阅读样章，当前代码并没有已接通的公开专题路由。UI-only 阶段不得把它作为会跳 404 的主导航链接，也不得以假数据冒充已发布内容。文化预览保留在历史主题工作室；首页没有有效主题输入时不渲染主题卡或空占位。
- 日后公开专题后端上线，是否把知古升为固定主导航属于该阶段信息架构调整，不在这次视觉改版中暗中实施。

### 4.3 后台与深层操作页

- 后台电脑端使用同一品牌的侧栏和工作区；手机使用可展开的“管理菜单”，关闭后隐藏项不抢焦点，切换路由后收起。
- 比赛、战术、监控可保持业务所需的信息密度；统一表头、标签、间距、表单、反馈和边界，不套首页海报布局。
- 比赛十人数据沿用同一份语义表，窄屏按已有规则呈现选手记录；不为了手机另复制一份数据结构。
- 战术地图保留操作面积、阵营辨识、坐标键盘替代路径和只读状态。横屏不挤掉确认、保存和退出入口。

## 5. 开屏和交互动画

- 用 v4 的 CSS/SVG「朱印落款 → 墨线展开 → 标题浮现 → 淡出」替换旧星光 Canvas 开屏，目标总时长约 1.86 秒。电脑和手机同一设计，按尺寸调整比例。
- 保持现有 `ArenaIntro`、`replayArenaIntro()` 对外调用方式和重播入口，不让页面分别挂载一套开屏。
- 同一标签页会话首次进入合适的标准页面时自动一次；切换页面、刷新、重新挂载不能无意重复。sessionStorage 不可用时仍需使用内存兜底避免当前文档反复自动播放。
- 登录/注册、后台、debug、正在显示关键业务弹窗时不自动播放。庄重专题预览不播放庆祝式开屏；未来有效庄重主题需要沿同一策略显式抑制装饰动效。
- 支持跳过和 Escape，重复点重播不叠加实例。播放时背景 inert 与滚动锁定必须精确恢复原值；跳过、完成、路由变化、切到后台和卸载都要清理计时器/监听并恢复焦点。
- `prefers-reduced-motion` 下不自动播放；手动重播只显示短暂静态标识，不强迫运动。不得让核心内容等待动画完成才获取或渲染。
- 运行中开启减少动态效果时立即结束开屏；会话键保持 `yanwu:intro-seen:v1`、重播事件保持 `yanwu:replay-intro`，避免换视觉时破坏原有接入点。
- 普通过渡统一 150–300ms，仅作用于必要的 opacity/transform 等属性；不新增常驻粒子、持续 Canvas/RAF 循环或鼠标全页面扫描。
- 路由进入动画只保留一处所有者，整理 `template.tsx`、`PageEntrance` 与旧 CSS 的叠加；登录成功揭幕保留回跳语义并统一风格，不能与开屏重复锁定交互。
- 撤下与纸墨风格冲突的旧光球、卡片追光和玻璃高光运行入口。只清理明确失去引用的旧样式，不大范围删测试或业务代码。

## 7. 架构和业务边界

- 权威依赖方向仍以 `docs/architecture/code-architecture.md` 为准：`app/web → features → core`，基础设施留在 `lib`。
- 新布局、视觉与交互放 `src/web`；不得直接 fetch、查 Prisma/Redis、调整爬虫或分队算法。已有 app 内 JSX 如需整理，只做必要展示迁移，不带入业务重构。
- 保留 features 客户端 API、认证、按需资源调度、SSE/轮询释放、上传与 OCR 合同，不因视觉改版增加轮询、并行数据请求或常驻缓存。
- 历史主题仍是 UI-only：保存、发布、正式反馈等未接通能力保持禁用及解释。临时草稿不等于数据库保存；保留当前身份隔离，不虚构已审核来源。
- 庄重纪念不与击杀、连胜、胜率或游戏庆祝同卡呈现；没有真实审核内容就保持预览身份。
- 不启动数据库、不迁移 schema、不访问生产、不修改部署/CI或服务器进程。先前内存排查和后端任务不因本次改版被宣称解决。
- 不引入新动画依赖、远程字体或全站截图生产接口。测试夹具只存在测试宿主中，正式构建不可读到测试身份/假数据开关。
- 在 `codex/history-theme-system` 当前目录开发，保留用户其他未跟踪文档；不推送、合并或部署。

## 8. 落地结构

- 以根布局、`ThemeProvider`、`ThemeLayout`、`Header`、`Dock`、`AdminShell` 和 `ArenaIntro` 为共享入口，保留可复用接口。
- 在 web 样式内建立明确的 token/共用组件/页面族/动效分工。移除旧视觉入口后，在原有作用位置替换；不得继续尾部叠加另一整套覆盖 CSS。
- `globals.css` 保留必要基础、功能布局和可访问性规则；清理前先盘点消费者，不让旧变量失联或淡色正文留在纸白背景。
- 原子组件统一按钮、输入、选择器、状态标签、表格、错误/空态、弹窗与反馈。危险红和阵营色仍有独立语义。
- 按“共享基础与开屏 → 公共/身份/资料与内容页 → 赛事/比赛/战术 → 后台 → 全站回归与截图”组织可独立验证的实施批次。每一批都使用本规范，不重新挑选视觉风格。
- 完成后更新 `docs/design/ui-system.md` 以反映实际实现，不能让旧“峡谷之夜”文档仍宣称是现行视觉。完成前本文与旧文档分别标明目标/当前事实。

## 9. 验收与交付

### 9.1 可访问性与状态

- 主要控件至少 44×44 CSS px；普通文本对比度至少 4.5:1，大字至少 3:1；状态不只依赖颜色。
- 320px 无页面级水平溢出，不用在 html/body/main 上裁切来掩盖。必要宽表只能在有名称、可聚焦的局部区域滚动。
- 保留标题层级、可见 label、表格 caption/th、Tab/方向键、Escape、焦点恢复、路由当前项和只读/禁用语义。
- 200% 字号/缩放、长名字、长标题、加载和失败状态仍可读可操作。手机安全区、横屏、弹窗滚动和 Dock 末尾遮挡单列检查。
- 旧测试中纯视觉断言随已认可设计准确更新；不得删测试、关闭架构检查、continue-on-error 或宽松 any 掩盖失败。

### 9.2 验证层次

1. 基础检查：architecture、typecheck、core、lint、build，以及相关移动路由、设备中转、认证回跳合同。
2. 无数据库 UI 回归：通过已有隔离组件宿主和受控客户端夹具测试真实组件，核对菜单、输入、弹窗、动画、权限状态与恢复动作；夹具不得泄漏至产品。
3. 浏览器矩阵：320×812、375×812、390×844、768×1024、812×375、1024×768、1440×900。覆盖手机/桌面 UA 与同上下文切换，并核对 CSS 响应式而非只看路由前缀。
4. 开屏检查：自动一次、刷新不重播、手动重播、连续点击、跳过/Escape、后台切换、路由卸载、减少动态效果、其他弹窗存在、存储不可用、滚动/focus/inert 精确恢复。
5. 实现完成后独立复审；发现问题修正后重跑有关检查。

数据库相关端到端读写测试在当前“数据库延期”范围下不运行；交付明确区分静态检查、真实组件夹具验证和未进行的真实数据库流程，不拿视觉截图冒充完整业务联调。

### 9.3 截图交付及完成条件

- 26 类正式页面各交一张电脑图和手机图，至少 52 张正常/合法可达状态图；登录受限、空数据、出错等关键状态另列，不用同一首页截图重复充数。
