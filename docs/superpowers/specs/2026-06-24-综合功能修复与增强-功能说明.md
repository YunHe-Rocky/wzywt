## 1. 踢次房主需先降级

**现状：** `kick/route.ts` 只阻拦 target.role === "owner"，次房主可直接踢出，admin 记录残留。

**改动：** `POST /api/tournaments/[id]/kick`

- 踢之前检查 target 是否为 co_owner
- 若是，在同一事务中先删 `tournament_admins` 再删 `tournament_players`
- 前端 `TournamentDetail.tsx`：`canKick` 条件中，target 是 co_owner 时按钮文案改为"降级并踢出"

## 2. 次房主主动弃权

**新增路由：** `POST /api/tournaments/[id]/admin/resign`

- 仅 co_owner 可调用
- 删除自己的 `tournament_admins` 记录
- 保留 `tournament_players` 记录，降为普通选手
- 房主(owner)不可弃权

**前端：** 管理员控制栏增加"辞去管理"按钮，仅次房主可见

## 3. 赛事大厅公开/私有展示

**首页（`/`）：** 展示所有 `status=recruiting AND isPublic=true` 的赛事（已有 `/api/tournaments/public`），移除公告非空过滤

**赛事大厅（`/tournaments`）：** `GET /api/tournaments` 改为返回三类：
- 我加入的赛事（现有逻辑）
- 我创建的赛事（现有逻辑）  
- 公开且招募中的赛事（新增，排除已加入的）

前端增加页签或在同一列表中展示。创建赛事的公开/私有切换保持不变。

**公开赛事卡片** — 显示房间名、编号、人数、截止时间，提供"加入"按钮

## 4. 官方公告爬虫

**问题：** 监控器检测变化后未触发真正的新闻爬取；`/api/official-news` 每次自己抓，选择器失效后落入 fallback 硬编码数据。

**修复链路：**

```
monitor checkNews() 检测到变化
  → 触发 news scraper 爬取新闻列表
    → 存入 kv_cache (key: 'official_news', value: JSON)
      → GET /api/official-news 从 kv_cache 读取返回
```

**改动：**

- `monitor/index.ts`：`runMonitorAndScrape` 中 news 分支改为真正调用爬虫函数，抓取标题+日期+链接，写入 `kv_cache`
- `official-news/route.ts`：不再自己爬，改为从 `kv_cache` 读缓存 JSON；缓存未命中时执行一次爬取并写入
- 爬取逻辑：修复 CSS 选择器，正确提取日期格式（`YYYY-MM-DD`）

**日期修复：** 从 HTML 中正确解析日期字段，不再依赖 `span:last-child` 等脆弱选择器。抓不到日期时用当天日期标记。

## 5. 房间公告

**问题：** 首页 `setRooms(d.tournaments.filter(t => t.announcement))` 要求公告非空，无公告则永远空白。

**改动：** 首页去掉 filter，展示所有公开招募中的赛事。

- 有公告的：显示公告摘要
- 无公告的：显示"暂无公告"

## 6. 忘记密码

### Schema 变更

```prisma
model User {
  // 新增字段
  email             String?   @unique
  emailVerified     Boolean   @default(false) @map("email_verified")
  resetCode         String?   @map("reset_code")
  resetCodeExpires  DateTime? @map("reset_code_expires")
  resetCodeAttempts Int       @default(0) @map("reset_code_attempts")
}
```

### 注册流程变更

1. 注册页新增"QQ邮箱"输入框 + "发送验证码"按钮
2. 点击发送 → `POST /api/auth/send-code?type=register` → 生成6位数字 → 存库 → QQ邮箱SMTP发送
3. 用户输入验证码 + 密码 → `POST /api/auth/register` → 校验验证码 → 创建用户
4. 前端校验：@qq.com 后缀、60秒发送冷却

### 忘记密码流程

1. 登录页新增"忘记密码？"链接 → 弹出 Modal
2. 步骤1：输入邮箱 → `POST /api/auth/send-code?type=reset` → 校验邮箱是否已注册 → 发送验证码
3. 步骤2：输入验证码 + 新密码 + 确认密码 → `POST /api/auth/reset-password` → 校验 → 更新密码

### QQ邮箱 SMTP 配置

环境变量：
```
EMAIL_HOST=smtp.qq.com
EMAIL_PORT=465
EMAIL_USER=your-qq@qq.com
EMAIL_PASS=授权码（非QQ密码）
```

依赖：`nodemailer`

**验证码存储：** 6位随机数字，明文存储（有效期仅5分钟，过期清除）。验证通过后立即清除 resetCode 字段。

**emailVerified：** 注册时验证码校验通过后设为 `true`，标记邮箱已验证。

### 异常处理

| 场景 | 处理 |
|------|------|
| 邮箱格式不对 | 前端校验，提示"请输入有效的QQ邮箱地址" |
| 邮箱未注册（忘记密码） | "该邮箱未绑定任何账号" |
| 邮箱已注册（注册） | "该邮箱已被使用" |
| 60秒内重复发送 | 按钮置灰倒计时，提示"请N秒后再试" |
| SMTP发送失败 | "邮件发送失败，请稍后重试" |
| 验证码错误 | "验证码错误"；连续5次锁定15分钟 |
| 验证码过期 | "验证码已过期（5分钟有效），请重新发送" |

## 7. 账号注销

### API

`DELETE /api/auth/me` — 需要传入密码验证

执行：
1. 验证密码
2. 级联删除所有用户数据（tournament_players, tournament_admins, role_preferences, hero_powers, temp_applications, admin_operations）
3. 删除用户记录

### 前端

个人空间页面底部增加"危险区域"卡片：
- 红边框 + 红字标题"危险区域"
- 说明文字："注销后所有数据将被永久删除，无法恢复"
- "注销账号"按钮（红色）

点击后弹出确认 Modal：
- 步骤①：输入 `DELETE` 确认
- 步骤②：输入密码验证身份
- 两个条件均满足后"确认注销"按钮激活
- 取消按钮（灰边框）与确认按钮（实心红）明显区分
- 横向排列：取消 | 确认注销
