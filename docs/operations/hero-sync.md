# 英雄、皮肤和技能同步

同步与发布分开执行。先完成部署和健康验收，再由管理员后台提交英雄同步任务，或在项目目录运行：

原生 PM2 手动执行时，工作目录使用当前运行的 `<runtime>/current`，以读取当前 `.env` 并写入 Web 实际读取的英雄图片目录。管理员后台提交任务由当前 Cron 执行，可直接复用它的目录和资源限制。

```bash
# Docker Compose：使用现有配置、持久目录和任务锁
node scripts/compose.mjs sync-heroes

# 原生环境：读取本项目环境，执行数据及图片两个阶段
npm run sync-heroes
```

后台任务由独立 Cron 处理；不要同时启动第二套 Cron。任务锁防止手动同步、定时同步和监控同时修改同一份英雄数据。

## 数据来源和版本

英雄目录与皮肤名称以[官方英雄 JSON](https://pvp.qq.com/web201605/js/herolist.json)为主；HTML 名单补齐未出现在 JSON 的英雄。皮肤序号严格跟随该英雄的官方名称列表顺序，保留同名皮肤，不把两份皮肤列表按名称合并。JSON 没有皮肤名称时才读取经过英雄身份校验的详情页。

技能优先读取目录中 `id_name` 对应的官方页面。2026-11-04 核对发现，官网数字页仍返回 HTTP 200，但内容可能落后于拼音页：

- 扁鹊的[数字页](https://pvp.qq.com/web201605/herodetail/119.shtml)“善恶诊断”冷却为 5、消耗为 60；[拼音页](https://pvp.qq.com/web201605/herodetail/bianque.shtml)冷却为 10/9.6/9.2/8.8/8.4/8、消耗为 30。
- 孙悟空的[数字页](https://pvp.qq.com/web201605/herodetail/167.shtml)“斗战冲锋”冷却为 8/7.4/6.8/6.2/5.6/5、消耗为 50；[拼音页](https://pvp.qq.com/web201605/herodetail/sunwukong.shtml)冷却为 6/5.8/5.6/5.4/5.2/5、消耗为 45。

上述差异只用于解释来源优先级和回归样例，不在代码中写死当前技能数值。同步按网页声明的 GBK 或 UTF-8 解码，并核对页面中的英雄编号和名称；已存在英雄的拼音页不可用时保留原技能，不用数字旧页覆盖。新英雄首次初始化、或官方目录未提供拼音名时，才允许使用通过身份校验的数字页。

## 失败与重试

目录来源不完整时，同步在修改目录前失败。某位英雄详情不可达、身份不符或技能结构不完整时，保留其原有技能 JSON 与技能表记录，其余可用数据和图片继续刷新。图片阶段结束后，任务报告部分失败，并且不写入“最近成功同步”标记；恢复网络或确认官方页面后重新执行同步。

每位英雄的 JSON 和技能表在同一数据库事务中更新。技能表重建失败会回滚该英雄的修改，不留下“JSON 已更新但技能行被删空”的状态。

图片采用同目录临时文件和原子替换；同一来源 URL 最长缓存 24 小时后重新下载。旧版只保存 URL 的永久缓存会在下一次同步刷新一次。皮肤下载只尝试该英雄、该序号的官方皮肤图片，不把头像写入皮肤文件；如果旧缓存来源明确为头像，会移除这张已确认错误的生成缓存。下载失败不会删除其他有效图片或业务媒体。

代码测试验证来源选择、失败保护、事务边界、编码和缓存刷新。上线后仍需执行一次同步，并在电脑和手机英雄页核对皮肤名称、图片及技能；官网自身未更新的游戏改动不会由系统猜测补全。
