# v1.0.2：UI 拆分与体积整理

## 实施范围

- `MatchWorkspace` 保留路由与页面编排，独立出统计表、逐行编辑、截图/OCR、提交、异议、纠错界面，以及草稿和操作 hooks。原有权限、草稿恢复、参团率换算、已保存数据优先级与 API 参数保持不变。
- `TournamentDetail` 独立出类型、阵容、公告、成员、访客、管理和结果区；容器保留数据与操作。选将面板在打开页签时加载，保留仅看本队、仅修改本人英雄的规则。
- 工作区、后台和调试 CSS 随对应组件加载；桌面与移动端共用入口。主题临时预览仍应用完整主题样式。
- 生成媒体与下载的 FFmpeg 不再纳入当前 Git 树。制作脚本和本地成品保留；独立的 119,639 字节、20 秒 H.264/AAC 样片替代 11,881,174 字节宣传视频测试依赖。
- `.gitattributes` 使部署使用的 `git archive` 排除 `artifacts`、`.planning`、`.superpowers` 与根目录工作笔记。保留运行源码、公开资源、部署脚本、Prisma migrations 和测试样例。
- 按用户授权，删除 4,773 个可重建的录屏帧和渲染中间文件，实际释放 996,002,325 字节（约 950 MiB）。无 Git 历史重写，历史克隆体积仍包含旧媒体。

`MatchWorkspace` 从 40,818 B / 565 行降为 6,713 B / 137 行，新增模块最多 166 行；`TournamentDetail` 从 40,593 B / 901 行降为 11,877 B / 265 行。均使用物理行数，未通过压缩代码减少行数。

实现暂存树的部署 tar 实测约 13.4 MiB，基线 `acc3f65` 为 143.3 MiB，减少约 91%。此数值不包含 `npm ci` 后依赖和生产构建产物；版本登记文档会使最终源码包略有变化。

## 构建资源口径

基线为 `acc3f65`。统计 `.next/app-build-manifest.json` 中根布局、模板及页面的去重 CSS/JS 文件大小；gzip 按每个文件独立计算。不包含 API 数据、图片、浏览器缓存和按需 chunk，不是用户网速或加载耗时测量。

| 资源 | 整理前 | 整理后 |
| --- | ---: | ---: |
| 首页 CSS | 164,360 B | 107,172 B |
| 首页 CSS gzip | 32,835 B | 22,279 B |
| 房间页首屏 JS | 492,641 B | 465,953 B |
| 房间页首屏 JS gzip | 149,611 B | 141,796 B |

首页 CSS 减少约 35%，房间页 JS 减少约 5%。模块拆分本身不保证每个页面体积都下降；战绩录入主要收益是可维护性。

## 验证边界

通过架构检查、TypeScript、核心测试、草稿/可见性回归、lint 和最终生产构建。lint 为 0 错误、18 个既有图片提示。

`test:e2e:yanwu` 全量通过：26 类正式页面、52 个两端基线、七种宽度及调试/主题/工作区交互；新增选将懒加载检查覆盖本人编辑、对侧不可见和原 PUT 参数。`test:e2e:combat-admin` 使用独立小样片通过实际上传、播放、seek、重试和管理回归。抽看桌面房间及移动战绩截图，页面布局正常。
