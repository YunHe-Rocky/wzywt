# 演武动态与后台发布复查

## 本次范围

- 动态独立页面、桌面和手机入口、访客登录引导。
- 300 秒 / 512 MiB 视频上传配置、前后端元数据验证、上传进度和取消。
- 原生 Range 播放、缓冲提示与保留进度重试。
- 共享后台布局、概览、动态搜索、隐藏、恢复和删除确认，保留既有用户/赛事/英雄/公告/设置功能。
- 本次不引入 FFmpeg/HLS 或多内核转码，不修改生产部署。

## 复查修复

1. 后台布局通过实时身份校验，避免旧管理员 Cookie 跳过禁用、降权与会话版本检查。
2. 管理动作只接受字符串枚举；数组等异常输入不能经字符串转换后落入删除分支。隐藏/恢复使用条件更新，避免复活正在删除的动态。
3. React StrictMode 重复挂载后恢复视频地址。原实现已在浏览器复现地址被清空，修复后开发/生产模式均通过。
4. 客户端和服务器使用配置的上传总超时；配额预留覆盖超时及验证余量，异常断开关闭输入流。
5. 发布后回到第一页；动态加载失败可以重试；后台操作错误在确认弹窗中显示，不清空已加载列表。
6. 历史发布测试改用可播放 MP4，适配折叠发布入口和真实 Range 大小；数据库测试增加隔离环境保护。

## 验证

- `npm run check`：完整检查通过。Windows 无法覆盖的 Unix mysqldump/目录权限用例仍由 Linux CI 执行。
- `npm run test:combat-video`：MP4/WebM、300/301 秒边界、损坏元数据、大小限制、失败清理、请求超时/中断及管理动作参数通过。
- `npm run test:e2e:combat-admin`：开发 StrictMode 与生产模式通过。覆盖 1440/390/320px、导航、搜索、确认/取消、错误恢复、访客守卫、第二页发布和真实 MP4 播放/拖动/重试。数据服务隔离，不写业务数据库。
- `npm run lint`：0 错误，18 条已有图片提示。
- `npm run build`：通过。
- `npm audit --omit=dev --audit-level=high`：0 漏洞。
- 新增视频检查与浏览器回归已加入 CI；数据库预留时长用例由 MySQL 8.0/8.4 CI 执行。

## 上线配置

生产 `.env` 不包含在提交中。按 [媒体配置说明](../operations/media-operations.md) 同步三个 `COMBAT_VIDEO_*` 设置，确认现有 Nginx 上传上限覆盖 512 MiB 文件及 multipart 开销（参考值 516m）。原每日上传配额与磁盘保护继续生效。

本次检查覆盖变更及其关联调用链和项目自动检查，不代表对全部业务场景或线上网络作出无缺陷保证。
