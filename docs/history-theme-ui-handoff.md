# 历史主题：UI 阶段交接

本轮按 2026-09-19 的最新要求“只把 UI 搞完，边界做好收尾工作”实施。此文档界定交付范围，不表示原完整系统或远端 CI 已通过。

## 入口与使用边界

- 桌面后台：`/admin/history-themes`；手机版：`/m/admin/history-themes`。
- 两个入口沿用既有管理员服务端权限布局，并禁止搜索引擎索引。普通用户不获得预览权限。
- 编辑预览只在当前浏览器文档的内存中保留一份临时内容，不写浏览器持久存储、数据库或文件。站内前进/后退可恢复，刷新或关闭将清除并请求浏览器显示未保存提示（最终提示行为由浏览器决定）。退出登录或身份不匹配时清除，不能当作正式草稿保存。
- 示例只是排版说明，不是已核验史料或已发布主题。近现代和人物内容不能以预览状态冒充已审核内容。
- 保存、提交审核、审核通过、发布和受控上传未接后端，不产生成功提示或伪记录。
- 45 天视图是日期布局；日期上显示“未计算”，不假造触发结果或撞期胜者。
- 首页仅安装空展示插槽；没有主题数据就不占空间，不调用新接口、不新增后台轮询。示例不会出现在公开首页。
- 公开详情路由尚未开放；管理员在同一预览中切换卡片与详情，不跳转到不存在的主题页面。

## 后续接入契约

展示契约在 `src/features/history-theme/presentation.ts`，组件在 `src/web/components/history-theme/`。现阶段契约只服务 UI，不能替代服务端鉴权、持久化及发布门禁。

1. API 只返回公开白名单字段；不得把 ORM 实体、创建人/审核人标识、草稿和内部审核意见传给展示组件。
2. 首页只加载小卡片字段，正文和素材按详情需要加载。首页主题请求独立降级，不并入会使房间/公告一起失败的请求链。
3. 服务端负责时间窗、资格、下架、缓存 revision 和边界 TTL；前端过期隐藏只是辅助防护，不能当作发布授权。
4. 真实详情路由、反馈提交、资源注册、上传/授权校验、来源治理、双人审核及审计，必须在后端完成后才启用对应操作。
5. 完整的农历/节气 provider、迁移、临时数据库验收、45 天预计算和定时任务，仍是原计划的延期项。
6. 所有图片都需要通过后续受控素材管线；Markdown 不能绕开素材审核加载远端图片。
7. 为保持 UI 局部边界，未加入全站导航拦截：浏览器前进/后退不承诺先弹确认框，而是保留临时编辑。后续如需强制导航确认，应单独设计统一路由契约，不能在此组件篡改全局 history。

## 验证方式

`npm run test:e2e:history-theme` 使用项目已有 Node Playwright 与真实 React 组件/CSS，独立回环测试服务器不连接数据库。可通过 `E2E_BROWSER_PATH` 指定本机 Chromium/Edge；`E2E_BROWSER=webkit` 使用已安装的 Playwright WebKit。截图输出在忽略目录 `test-results/history-theme-ui/`。

这一测试替换 Next 路由与登录态提供器，只证明 UI 行为；不等同于真实登录、后端发布、数据库迁移或生产环境验收。测试文档由 Playwright 直接提供，避免本机 HTTP 内容过滤软件注入脚本；真实 JS/CSS/图片仍走回环 HTTP，所有外部请求仍被记录并拒绝，没有域名豁免。
